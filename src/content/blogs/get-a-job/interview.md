面试一般分为多个轮次：

1. 一面：HR 面，初步沟通；
2. 二面：技术面；
3. 三面：沟通到岗时间和薪资。

## 自我介绍

一面和二面都需要自我介绍，一般情况下由面试官提问展开。

- 面向岗位需求，结合自己的身份和经历进行介绍；
- 如果公司有国际业务，或者是外企，最好准备一份英文自我介绍。

---

## 一面：HR 面试

一面一般通过电话进行，可能是微信电话，也可能是手机通话。

初聊会涉及较多方面。

---

对于非技术面试，可能会由 HR、总经理、投资人等提问，侧重公司介绍、答疑和职业规划选择等。

### 面试官可能提问

- 你对公司的期待是什么?
- 你自己有没有什么长期项目?
- 你自己的职业规划 和 技术方向?
- 你希望在公司做成什么事/项目?
- 如果我我们公司给你发 Offer , 你会考虑来我们公司嘛?

### 面试者需要向目标公司了解

HR 更适合回答招聘流程、组织安排和制度类问题。可以根据前面的沟通选择两三个重点询问，不需要把清单全部念一遍。

#### 岗位与招聘背景

- 这个岗位是新增岗位还是人员补招？目前为什么要招聘？
- 岗位属于哪个部门？汇报对象是谁？
- 公司对这个岗位最看重的能力是什么？试用期或实习期的主要目标是什么？
- 后续还有几轮面试，分别由谁参加，大概考察哪些方面？

#### 实习、转正与发展

- 实习生和正式员工承担的工作有什么区别？
- 是否有转正机会？转正的时间、标准和流程是什么？
- 公司是否有导师、培训或定期反馈机制？
- 这个岗位常见的发展路径是什么？

#### 工作安排与基本制度

- 工作地点、工作时间和考勤方式是怎样的？是否需要出差？
- 薪资结构、发薪时间和试用期薪资如何计算？
- 加班、调休、请假和休假的制度是怎样的？
- 公司是否提供工作电脑、餐补、交通补贴或住宿支持？

对方也可能反问你从外地来这里要怎么生活，判断你是否适合异地工作。例如，我就被问过在这里租房和消费大概要多少，并由此引入了薪资话题。

## 二面：技术面试

---

技术面试的面试官可能是对应岗位的工程师，侧重考察技术能力。

1. 自我介绍
2. 项目经历
    1. 可能会着重问你一个项目，你要具体的说出来
    2. 一定要记得给他看作品集，你开共享屏幕来边看边讲最好
    3. 可能会跟着你项目的节奏问你公司的一些情景问题，比如遇到技术栈和岗位任务重合的时候，我之前就被问卡尔曼滤波器的应用的问题，还有目标检测与跟踪
    4. 项目经历一定不要自我沉醉来讲，要让别人听得懂，听得明白，知道你干的啥
    5. 说清楚自己项目中的开发缘由，职责，技术栈，项目效果等等
3. 公司业务
    1. 干啥的
    2. 有什么
    3. 你需要做什么
    4. 你在我们公司相关业务这方面的技术了解多少
4. 个人规划
    1. 有什么打算
    2. 长期规划
        1. 学什么
        2. 干些什么
        3. 是否长期实习
    3. 来我们公司你会干些什么

### 反问技术面试官

技术面试官更了解实际业务、技术方案和团队工作方式。反问时应该结合面试中已经谈到的内容，优先追问自己真正关心、且对方能够回答的问题。

#### 具体工作与业务

- 这个岗位入职后主要负责哪个产品、模块或环节？
- 日常工作中，开发新功能、维护旧系统、排查问题分别占多大比例？
- 当前团队最希望新成员解决的问题是什么？入职前三个月希望做到什么？
- 产品主要服务哪些用户？目前处于验证、快速迭代还是稳定维护阶段？
- 这个岗位如何与产品、测试、算法、硬件或其他开发岗位协作？

#### 团队与工程流程

- 团队目前有多少人？成员如何分工，任务通常如何分配？
- 项目如何进行需求评审、开发排期、测试和发布？
- 使用什么版本管理和分支策略？在github是否有自己的组织？是否通过 PR 或 Code Review 审核代码？
- 团队有哪些编码规范、自动化测试、CI/CD 或上线检查机制？
- 项目文档和知识库如何维护？新人通常怎样熟悉代码和业务？
- 出现线上问题时如何响应？这个岗位是否需要值班或承担紧急支持？

#### 技术现状与挑战

- 项目当前的核心技术栈是什么？选择这些技术的原因是什么？
- 现阶段最大的技术难点、性能瓶颈或历史包袱是什么？
- 团队近期准备重构、替换或引入哪些技术？
- 面试中提到的某项技术，具体应用在产品的哪个环节？
- 对于这个难点，我理解可能采用某种方案，团队目前是怎样处理的？

#### 成长与评价

- 团队如何定义这个岗位做得好？有哪些明确的目标或评价标准？
- 新人是否有导师、设计评审或定期的一对一反馈？
- 团队中经验丰富的成员主要在哪些方向提供指导？
- 这个岗位未来可以深入哪些技术或业务方向？

#### 直属负责人与岗位稳定性

- 我的直属负责人是谁？平时如何分配任务、反馈问题和评价结果？
- 这个岗位为什么出现空缺？上一位成员是内部转岗、晋升，还是已经离开？
- 团队过去半年最大的变化是什么？接下来最重要的目标是什么？
- 如果我入职三个月后表现很好，具体会体现在哪些结果上？

> 反问不是问题越多越好。每轮选择两到四个最重要的问题，并根据对方的回答继续追问，会比照着清单逐项提问更自然，也更容易获得真实信息。

### 怎样判断回答是否可信

“团队氛围很好”“发展空间很大”这类回答信息量很低，可以继续要求一个具体例子：最近一次 Code Review 如何进行？新人上一次独立交付了什么？最近一次加班发生在什么时候、因为什么？

同一个关键问题也可以分别询问 HR、直属负责人和未来同事。回答不必完全一致，但如果岗位职责、加班情况、转正标准或招聘原因相互矛盾，就需要在接受 Offer 前确认清楚。

面试结束后及时记录对方的原话，并按照业务、职责、成长、管理方式、待遇和风险分别评价。不要只凭面试过程聊得是否开心做决定。

## 三面：薪资与到岗时间

到了这一步，需要把影响入职决定的信息确认清楚。

1. 对方询问薪资期望时，给出经过调查的明确范围，并确认薪资结构、试用期比例、奖金和补贴；
2. 确认 Offer、劳动合同或实习协议中的岗位、工作地点、期限和违约条款；
3. 确认到岗时间。可以积极，但要根据离职、搬家和住宿等实际情况给出可靠日期；
4. 如果前面仍有关键问题没有得到明确回答，应在接受 Offer 前再次确认。

## 最后

你提供邮箱，对方发送 Offer。收到后先核对书面信息是否与沟通一致，再决定是否接受并等待入职。

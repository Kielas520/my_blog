简历我也不怎么会写，但是你必须清楚一件事情：要简洁、精炼且对口。

## 简历

### 个人信息

- 姓名
- 学历
- 手机号
- 邮箱
- GitHub 账号
- 求职意向
- 个人网站或作品集链接

证书、微信号和个人照片不是所有岗位都需要，应根据招聘要求和行业习惯决定是否添加，不要挤占重要项目的空间。

### 教育经历

写清学校、专业、学历和就读时间。课程、成绩、奖项只保留与目标岗位有关、且能体现优势的内容。

### 自我评价

简单描述相关经历、核心优势和求职方向即可。如果不能提供比项目经历更多的有效信息，也可以不单独设置这一栏。

### 技能树

根据目标岗位筛选技术栈，按熟悉程度或领域分类。只写自己能够解释原理、使用场景并接受追问的内容，不要把接触过的工具全部罗列出来。

### 项目经历

包括工作经历和比赛经历，重点注意：

- 一定要选择最相关的经历；
- 在于精，不在于多；
- 说明自己的职责；
- 列出使用的技术栈；
- 说明遇到的问题、采取的行动和最终结果；
- 尽可能用速度、精度、资源占用、用户量或交付时间等数据说明效果；
- 区分团队成果和个人贡献，确保简历上的每一句都能在面试中展开。

完成后，再对照 JD 检查关键词和项目顺序。最相关、最能证明能力的内容应该最先被看到。

## 作品集

作品集是简历中项目经历的延伸，主要解决简历上写得不够具体的问题。

每个项目可以按照下面的结构展示：

1. 项目名称和一句话定位；
2. 在线演示、视频或 GitHub 链接；
3. 项目背景、目标用户和自己负责的部分；
4. 核心方案、技术难点和选择这一方案的原因；
5. 最终效果、验证数据和后续可以改进的地方。

展示时注意：

- 图文并茂；
- 排版紧凑；
- 有看点；
- 可以从“相比于其他方案……”的角度展开；
- 要体现出自己的思考；
- 确保链接可以访问，README 中有运行方式，演示前隐藏密钥和敏感数据。
